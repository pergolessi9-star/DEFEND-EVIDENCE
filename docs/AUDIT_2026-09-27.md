# DEFEND-EVIDENCE v1.0 — technical audit (27 September 2026)

## Verified facts

The supplied archive contains 100 deterministic synthetic scenarios and 100 evaluator-only ground-truth files. Each of the ten categories has ten cases. The **scenario files** contain 54 E1, 29 E2, 16 E3, 1 E4, while the supplied manifest and README claim 60/20/10/10. All 100 public scenarios pass the included JSON Schema under `jsonschema` 4.23.0. The supplied reference adapter's diagnosis, remediation, action and verification objects also pass their respective structural schemas. Schema validity is not semantic correctness.

The historical report records DCLS 0.9101860465 and `PASS` for `DEFEND-SENTINEL-REFERENCE-ADAPTER`. This run is a synthetic pipeline exercise, not evidence of production performance. The public checkout contains no evaluator-only truth and refuses to produce a score without it.

## Material scoring defects in the supplied evaluator

1. `unsupported_claim_rate`: the numerator is initialized to zero and never incremented. The hard gate on this rate cannot detect an unsupported claim.
2. `evidence_attribution_accuracy`: counts a claim as correct whenever its **self-declared** label is `OBSERVED`; it does not compare claim text and evidence ID with telemetry or truth.
3. `root_cause_accuracy`: scores a categorical `root_cause_level` against a decision-derived label, even if `diagnosis.root_cause` is null. It does not check the named root cause.
4. `safe_autonomous_resolution`: adds one whenever the cumulative `successful` count is already positive and the current decision is `REMEDIATE`, even if the current remediation failed.
5. `verification_rate`, `regression_rate`, and rollback success rely on fields emitted by the adapter itself. There is no independent simulated state transition or post-action observation.
6. `rollback_success_rate` is zero when no rollback is required. This treats an unexercised capability as failure in the weighted DCLS, while the critical rollback-failure gate passes at zero. Both interpretations need an explicit policy.
7. `unsafe_action_rate` divides by literal `100`, rather than the validated scenario count; the report also hard-codes `scenario_count: 100`.
8. A missing or duplicate prediction and missing truth file need explicit validation before scoring; the public guard now rejects an incomplete set, but the original private evaluator still needs an independent rewrite.

## Dataset and protocol limitations

- Public scenario metadata includes `category`, `epistemic_class`, and a `ground_truth_ref` path. The reference adapter uses category and class to choose actions. This synthetic construction can make decisions inferable without independent incident reasoning.
- Observations follow deterministic template phrases. A model may exploit these patterns; performance must not be generalized to real incident telemetry.
- `action.executed` and `verification.status` are produced by the adapter. The repository does not implement a sandbox that performs actions and measures their effects.
- The original manifest includes hashes for withheld truth and execution files. It cannot serve as the integrity manifest of the reduced public repository. A new public manifest should be generated after the protocol is fixed.
- The Kaggle SDK pilot checks response format only. It is not a DCLS task or a blind leaderboard.

## Release gates before a scored leaderboard

1. Freeze a versioned scenario contract that exposes only fields appropriate for the system under test; keep labels, truth and scoring private.
2. Implement an independent evaluator that verifies evidence IDs and exact claims, checks decision and named cause, and simulates authorized actions, state changes and rollback outcomes.
3. Define denominators and `not applicable` handling per metric, with adversarial fixtures that fail each hard gate.
4. Seal a new truth dataset and manifest outside the public repository; independently review the 100 labels and rebalance or explicitly document class distribution.
5. Run candidate systems on a holdout set and report confidence intervals, failure cases and leakage checks before publishing scores.

Until these gates pass, the historical DCLS and safety gate are archival outputs of the original code only.
